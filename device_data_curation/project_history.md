# device_data_curation — Project history

## 2026-08-14 — Project created; plan drafted

- Scaffolded the subproject (sibling to `FDA_real_world_data/` and `no_meal_announcement/`): a curation layer that splits the raw BDDP device table (`dev.default.bddp_sample_all_2`) into cleaned, sanitized, orthogonal per-type event-grain tables in `dev.tbddp_curated`, Loop first, designed to generalize to the full TBDDP (all device families) and to support recreating the "Let's Talk About Your Insulin Pump Data" blog analysis.
- Wrote `architecture.md` (source/scope, design principles, draft table set, shared cleaning core, sanitization spec) and `dev_plan.md` (MVP-0..5 staged plan + TBDDP generalization notes + open questions).
- Wrote `exploratory/profile_bddp.sql` — the MVP-0 profiling queries (§0 DESCRIBE has never been captured for the raw table; §6 device census seeds the future TBDDP device inventory).
- **MVP-0 §0 captured**: `DESCRIBE` of the raw table run — 140 columns (all strings), categorized in `docs/bddp_profile.md`. Headline discoveries: top-level device metadata (`manufacturers`/`model`/`softwareVersion` → device inventory from upload rows, not deviceId regex), per-row `units` column (don't assume mmol/L), named `timezone` + `deviceTime`, lifecycle columns (`_active`/`deletedTime`/`_deduplicator` → curation needs an active-row predicate), `uploadId` spelling (FDA fixture's `uploadID` doesn't exist), PII-risk columns enumerated and blacklisted (`notes`, `location`, `name`, `serialNumber`, `transmitterId`, …), ingest artifacts (`expextedNormal` typo twin, `jsDate`, `_rescued_data`). `profile_bddp.sql` §1–§10 rewritten against the real schema; architecture.md updated (lifecycle-filter bullet, blacklist, loop_uploads columns).
- **MVP-0 §1 run**: per-type inventory — 19 types. Discoveries: 8 types no pipeline has ever touched (`controllerStatus`/`pumpStatus`/`alert`/`cgmSettings`/`physicalActivity`/`insulin`/`bloodKetone`/`reportedState`); the Tidepool-Loop-platform trio (exact window 2022-11-04→2025-03-19, 100% named timezone — the platform extract window, matching NMA's analysis window); **no `type='upload'` rows** (killed `loop_uploads` as planned); three mutually exclusive timezone regimes (named tz / deviceTime+offset / neither, with offset and deviceTime co-occurring almost exactly on legacy types); epoch-1970 and far-future event-time garbage → added `is_plausible_time` flag to the cleaning core; Mongo-JSON bad times negligible. §6a/§7a rewritten, §7g (new-type shapes) and §10a plausibility tails added to the profile queries; architecture + dev plan updated.
- **MVP-0 §6a run**: device-metadata census — `manufacturers`/`model` live on `pumpSettings`/`cgmSettings` rows (settings rows are the metadata carriers; no upload table needed). First TBDDP device-family inventory: Tandem, Insulet (Dash/Eros/OmniPod), Medtronic (modern MMT-* + legacy Paradigm), Animas, exotics (Sooil/Roche/Microtech/Weitai); CGM: Dexcom, Abbott Libre, pump-integrated Medtronic. Consequences: dropped `loop_device_metadata` from the table set (settings tables carry `device_family`/`manufacturers`/`device_model`; `device_inventory` becomes a derived dimension, Databricks-only); cleaning core gains model→family seed map, manufacturers-array dedup, and `is_test_device` flag (`Acme MyPumpModel` and `LoopKit MockCGMManager` exist in prod data); `CGMBLEKit` softwareVersion noted as a DIY-uploader marker.
- **MVP-0 §2 run**: writer census (tail truncated at the query LIMIT; full census on Databricks). Discoveries: null-origin = Tidepool-Uploader device stream (all `wizard` rows included); Loop identity fragmented beyond the drafted predicates (case-variant bundle id, personal-team-ID DIY builds, renamed HK sources) → predicate v2 (pattern-based) required, §5 query updated to size the delta; the Loop-fork ecosystem (iAPS/FreeAPS/Trio/…) is material and defaults to separate-source-family treatment (new open question); HK-relayed `smbg` from CGM-bridge apps is CGM data → `source_category` + `is_cgm_derived`; writer strings are localized, contain invisible unicode variants, and can embed personal names → raw writer strings blacklisted, normalized `source_app`/`source_category` via a regex writer seed map in `curation_common.py`; pen ecosystem spans InPen-via-HK and the `insulin` type.
- **MVP-0 §3 run**: categorical census — the curated tables' enum contracts. Discoveries: `bolus.subType='automated'` exists dataset-wide across far more users than the platform cohort (supersedes NMA's "doesn't exist" finding, which was Loop-cohort-scoped; likely CIQ/O5 auto-boluses — §3b query added to confirm writers); extended boluses (`square`, `dual/square`) are a substantial non-Loop population; `basal.deliveryType` = temp/automated/scheduled/suspend; `dosingDecision.reason` has 9 values incl. the large `updateRemoteRecommendation` remote-monitoring stream (FDA's `reason='loop'` excludes it); `smbg.subType` (scanned/manual/linked/null) + §2 writers → derived `glucose_sample_kind`; `deviceEvent.subType` enum settled — status events carry JSON suspend/resume provenance in `reason`, `prime`/`reservoirChange` give direct site-change events, `timeChange` is near-universal (clock bootstrapping), and `pumpSettingsOverride` is the non-Loop preset analog (§7h query added). Architecture table rows updated with the enums; TBDDP notes gain the non-Loop-AID-features point.
- **MVP-0 §3b run**: automated/extended-bolus writer cross-tab. `subType='automated'` has two writers — the platform's Loop-direct stream (a subset of platform users; invisible to NMA's HK-stream classification) and uploader-device AID pumps (thousands of users — the CIQ/O5-style population, hypothesis confirmed). Extended boluses are all uploader-device. Third test writer found (`org.tidepool.tidepoolKitTest`) → added to the test-writer flag list. `is_automated` documented as presence-only from subType, with the HK+Loop-direct cross-stream duplicate as an MVP-2 test archetype.
- **MVP-0 §4a run**: column-population census (delivery/glucose/carbs). Whitelists pinned: bolus gains `expected_normal_u` (interrupted boluses directly recorded; typo twin `expextedNormal` confirmed negligible); basal gains `percent` + parsed `suppressed_rate_u_hr` (percent-of-scheduled temps need the suppressed rate for delivery math); dosingDecision scalar whitelist confirmed (IOB/COB/recommended/requested; forecast arrays await §7b); deviceEvent calibration carries `value`+`units`, durations on suspends/overrides; cbg `trend` too rare to rely on; the status/alert/insulin/reportedState/controllerSettings types are all-JSON (zero scalar population) so their whitelists come from §7 shapes; wizard confirmed rich (carbInput/bgInput/IOB) for the TBDDP phase. Architecture table rows updated.
- **MVP-0 §4b run**: settings/lineage/metadata/PII column census. `uploadId` universal → every curated table gains `upload_hash` (closes the §6a lineage question); `deviceId` confirmed a device-stream property; `annotations` common enough to matter (CGM out-of-range clamps change value semantics) → §4c annotation-code census added, `loop_cbg` gains annotation-derived flags; PII blacklist validated live (notes on bolus, food/activity names, serials on pumpSettings); alert identity lives in `name` → alert-name enum seed map; deviceEvent rows carry `overridePreset`/`bgTarget` (FDA's type-less override predicate conflates the two sources — MVP-4 reconciles); pumpSettings singular-vs-plural schedule forms both present (parser handles both); wizard carries its own `bgTarget`.
- **MVP-0 §5-v2 run**: Loop-universe overlap. The universe is ~3× the platform cohort; HK-only DIY Loop is the largest segment (about two-thirds) — dosingDecision-keyed analyses cover a minority of Loop users, vindicating curation ≠ cohorting. A meaningful platform slice has no HK delivery stream (Loop-direct is their only insulin source — reconciliation must fall back per user). Pattern-only delta is a handful of users (predicate v2 = correctness fix, not population shift; pattern subsumes all exact predicates — sanity check passed). `loop_users` gains per-user evidence flags (`has_dosing_decision`/`has_hk_loop`/`has_loop_direct`/`is_pattern_only`).
- **MVP-0 §4c run**: annotation-code census. Annotations are namespaced driver-attached data-quality codes and become a first-class cleaning input: `bg/out-of-range` clamps on glucose (value = bound, not measurement) → `is_out_of_range`; **fabricated basal segments** (schedule-projected, not observed — several driver namespaces) → `is_fabricated`, with cross-brand TDD integrity implications for the blog recreation; `basal/unknown-duration` → flag; `uncertain-timestamp`; `status/incomplete-tuple` (open suspend/resume intervals); CIQ pumpSettingsOverride events heavily day-boundary-fabricated (stitching needed); medtronic600 smbg provenance codes refine `glucose_sample_kind`; split-extended-bolus codes (animas/insulet). Shared `parse_annotation_flags` helper added to the cleaning core; unknown codes QC-counted. Driver namespaces cross-check the §6a family map. Census read first-code-only; parser must handle full arrays.
- **Confidentiality rule established (Mark)**: dataset statistics — user counts, row counts, device/manufacturer breakdowns and shares — are **non-disclosable and must not be documented anywhere in the repo** (tracked or ignored), in commit messages, or in published artifacts. All count-bearing profile results and QC artifacts live on Databricks only; repo docs carry structure, methodology, and qualitative findings. `bddp_profile.md`, architecture.md, dev_plan.md, and this file were scrubbed accordingly; the rule is codified in the sanitization spec, `bddp_profile.md`'s header, and the project CLAUDE.md.
- Key design decisions (rationale in architecture.md): event grain, curation ≠ cohorting (no eligibility gates baked in), flags not filters, both insulin streams preserved with provenance, salted-SHA-256 `_userId` hashing at every export's final SELECT (salt `tbddp-curation-v1`, single-sourced), no raw JSON/preset names/device serials in outputs, single `MMOL_TO_MGDL = 18.018`, FDA-style pytest-free test harness, copy-adapt (not import) from FDA/NMA staging with parity checks against them as validation oracle.
