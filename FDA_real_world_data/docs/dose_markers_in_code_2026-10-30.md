## Where the code differs from draft 1

- **Missing automatic key.** Draft 1 says a September code review found the Medtronic driver can leave the automatic key off a temporary basal. In the code every Loop 3 release ships, it cannot: since September 2022 a Medtronic temporary basal read back from pump history is written with the flag false and turned true only when matched to the dose Loop sent. The flag was absent in builds before mid-2022: Medtronic before June 2022, Omnipod DASH before May 2022, and Omnipod Eros before June 2022. That fits the data, where the automatically-issued key first appears on an Apple Health temporary basal in 2022. Pump drivers outside these three were not checked.
- **What the key 0 means.** On Omnipod (Eros and DASH) a 0 marks a temporary basal the user set from the pod settings screen. On a Medtronic pump a 0 also marks an automatic temporary basal that was not matched to Loop's own record, so the key cannot separate manual from automatic there. This bears on the manual temporary-basal question and on any rule that drops the 0s.
- **Which app counts as Loop.** The proposed Apple Health rules read Loop's own app identifier, com.<team id>.loopkit.Loop. Every Loop build signs the app with it: Loop's project has appended .Loop to the base identifier since 2016 (Loop 70070c8, the same setting in Loop 3.4.0), and the browser build uses the same identifier. The filed census agrees: Loop-named Apple Health records carry that identifier, apart from a few under other identifiers. (Corrected 2026-10-30: the first pass read only Loop.xcconfig and missed the suffix the project settings add.)
- **Copies across the routes.** Both copies of a dose carry the dose's sync identifier: the Apple Health sample in its sync-identifier metadata, the plugin record in payload.syncIdentifier. If the uploaded Apple Health record keeps that metadata, the two copies can be matched exactly, in place of the minute-and-amount match.
- **The plugin's automated-bolus tag is needed.** Loop 3.2 releases sent automated boluses with subType normal, because the platform accepted subType automated from clients only from 2023-03-24; the record id still ended in bolus/automated. Today's plugin-route marker rejects subType normal, so it misses them; Loop 3.4.0 is the first release that sends subType automated.
- **The plugin's automated-basal tag includes some scheduled basal.** Since 2023-03-16 the plugin also uploads scheduled basal that Loop set automatically as deliveryType automated, so not every automated basal record is a temporary basal.
