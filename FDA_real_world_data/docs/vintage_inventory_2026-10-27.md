# Vintage inventory: what each issued document was rendered from (2026-10-27)

Execution plan Step 1.3 ([execution_plan_2026-10-27.md](execution_plan_2026-10-27.md)). A *vintage* is one state of the staged tables; a document's vintage of record is the set of analysis output files it was rendered from and the tables those files were computed from. This inventory records, per issued document, where the output files of record are, which tables produced them, and whether those tables still exist on Databricks. It holds no counts or results. It is the basis for `production_runs/snapshot_vintage.py`, whose manifest (one row per table with its `DESCRIBE DETAIL` last-modified time) is the verifiable companion to this page: every "still on Databricks" claim below was checked on 2026-10-30 against it and against each table's Delta history (§4 item 1).

Sources read for this page: the FDA and NMA `architecture.md` and `project_history.md`, the Drive folder listings and file dates under `510k/claude/`, the RPT-1001 and RPT-1008 report scripts (`510k/claude/scripts/`), `RFAI/data/README.txt`, and the pipeline definition.

## 3. What the snapshot does with this

`production_runs/snapshot_vintage.py` deep-clones every base table of `dev.fda_510k_rwd` (scratch and test tables excluded by prefix) beside its source as `<name>_vintage_<label>` (CREATE SCHEMA is refused on dev) and writes a manifest with each source table's row count and last-modified time. One run therefore captures both vintages as they stand today: V1 for everything the unsuffixed, `_box070`, `_box090`, IR-1002, stable-autobolus, and durability tables hold, and V0 for the `_box080` subtree and the `nma_*` tables. The check on §1 and §2 is each table's last data write in its Delta history (`production_runs/vintage_history.py`). The manifest's `source_last_modified_utc` cannot serve, because file maintenance and statistics commits move it without changing rows. A table whose last data write is after the date stated here was changed without a record, and the inventory is corrected before anything depends on it.

Where a document's base vintage no longer exists on Databricks (RPT-1001's §8-6 and §8-7, the IR-1 response, RPT-1008's anchor), parity is established against the output files of record on Drive, not against a re-run, and the repository-only output folders named above are filed on Drive before the corrected run.
